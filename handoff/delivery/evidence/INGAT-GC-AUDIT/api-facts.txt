1. V  List: GET /orgs/{org}/packages/{package_type}/{package_name}/versions; page (default 1), per_page (max 100,
      default 30), state (active|deleted, default active); 200/401/403/404 (rest-packages.md 619-668; openapi 32036-32086).
      Script: /orgs/<owner>/packages/container/<name>/versions?state=active&per_page=100&page=N; stops on a short page,
      refuses above 30 pages. No total count is returned, so paging to a short page is the documented way.
2. V  Get one: GET .../versions/{package_version_id} -> 200 (rest-packages.md 703-767). Script re-reads each id first.
3. V  Delete: DELETE .../versions/{package_version_id} -> 204; 401/403/404 otherwise (rest-packages.md 769-823). A public
      package version with more than 5,000 downloads cannot be deleted (rest-packages.md 775; deleting-restoring.md 14).
4. V  Restore: POST .../versions/{id}/restore -> 204, within 30 days of the deletion and while the namespace and version
      are not reused (openapi 32154-32162; deleting-restoring.md 223-226).
5. V  Version shape: id integer, name string, created_at date-time (required), metadata.package_type enum incl.
      container, metadata.container.tags array of strings (required inside container) (openapi 107506-107582;
      rest-packages.md 684-701). NV: that `name` is the manifest digest for a container version (the schema example is
      "latest"); the script uses `name` only for logging and the re-read equality, not for selection.
6. V  GITHUB_TOKEN may delete or restore package versions through the REST API when it has admin permission to the
      package; a repository whose workflow publishes the package gets the admin role by default; marked "currently in
      public preview and subject to change" (deleting-restoring.md 34-36; publishing-actions.md 20-22). A package linked
      before publication (org.opencontainers.image.source label, which image.yml sets) inherits the repository's access
      (package-access.md 15). NV: whether the live token is accepted for list and delete; the OpenAPI entries carry
      x-github enabledForGitHubApps: false (openapi 32085, 32118, 32151, 32189), and the REST overview says package
      endpoints need a classic personal access token (rest-packages.md 11). Fails closed either way (non-200 / non-204).
7. V  Rate limits: GITHUB_TOKEN 1,000 requests per hour per repository (rate-limits.md 58); secondary limits: 100
      concurrent, 900 points per minute per endpoint, about 80 content-generating requests per minute and 500 per hour,
      403 or 429 when exceeded (rate-limits.md 64-70, 113). The script is sequential; any 403/429 stops the run.
8. V  Concurrency: one running and, by default, one pending run per group; a newer pending run cancels the older pending
      one; `queue: max` allows up to 100 pending (concurrency.md 11-18). Supports not sharing a group with image.yml.

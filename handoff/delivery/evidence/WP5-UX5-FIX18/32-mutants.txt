M6 cannot be told apart by the suite, and cannot in the product either. The clock context raises one counter, `version`, for the page's own Check in and Check out and also when the tab
comes back into view on the Timesheet page (ClockProvider.tsx, `afterAction` and `onVisible`; that file is not an owned path of this task). So the page cannot tell the page's own action from a
return to the tab, and a refresh "on any change" is the same refresh. What keeps a change from elsewhere safe is the data guard, not the trigger: the fresh day is taken only when the day's
fields equal the day the editor holds (sameDayFields) and no session dialog or delete confirmation is open. M3 and M4 remove those two guards and the suite kills both; M6 only widens the trigger,
and the guards still decide, so every test passes by design. The existing "a day changed elsewhere reports a stale version and reloads" and "a stale session version at save reports the
conflict" pass on the unchanged product (21-newtest-on-base-log.txt, the first of the two), on the fix (24-newtest-on-fix-log.txt) and under M6.

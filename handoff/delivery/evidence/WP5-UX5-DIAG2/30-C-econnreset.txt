Which request, which side: a Node fetch (undici) issued by the TEST RUNNER process (SeedClient.raw, tests/e2e/fixtures.ts:371-376) to the built server on
127.0.0.1; the server side closed the connection (reset on a reused socket). Not a page navigation, not an in-page fetch.
Where: submission.spec.ts:67 (REGATE3 full-0314 trace: last good API call at 6.78 s, then 8.6 s with no trace step, then the failure at 15.4 s) and automation.spec.ts:118,

callers submission.spec.ts:102, automation.spec.ts:158, :165, :290) and fetch again in the same tick.

Mechanism: spawnSync blocks the runner's event loop. The server (@hono/node-server serve() at src/server/index.ts:59, default Node http keepAliveTimeout 5 s, no
other timeout set in src/) closes the idle keep-alive socket after 5 s. The blocked runner cannot read the close, and the next fetch reuses the dead pooled socket.
Timers involved are libuv timers (monotonic), not Date: the shifted wall clock plays no part. The preload only slows each spawned CLI (it loads shiftclock.mjs).

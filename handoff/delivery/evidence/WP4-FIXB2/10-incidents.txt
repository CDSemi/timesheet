   The brief forbids feeding scripts to python or node through stdin. It ran nothing ("Python was not found"; the Windows
   Store alias). No file was read or written. Every later probe is a file under <task>/probes run by path.
2. A first attempt to append the new reader tests with `cat >> tests/... <<'EOF'` failed in bash (quoting error) and wrote
   nothing (line count unchanged, checked); the block was added with the Edit tool. Two small edits to owned files were made
   with `sed -i` (renaming an inner helper call in xlsxReader.ts; three lines of the existing findings-cap test).
3. Tests adjusted after the first green run, all in owned test files, all rerun red against the baseline (02, run 2):
   a. the sheet-name test: a 1 MiB name is refused earlier by the start-tag limit (`tag_too_large`), so a 10 000-character
      name was added for `sheet_name_too_long` (both asserted, in the reader and over HTTP);
   b. the sweep's shared-string shape uses `<si/>`: `<si><t>s</t></si>` costs two markup openings per string, so the
      opening limit is reached first (the refusal is still typed, but not the code under test);
   c. after maxTotalElements was lowered to 200 000, the sweep's "four parts of long-valued cells" was resized (24 000
      cells a part), and the existing WP4-FIXB test "caps the stored findings" went from 3 x 40 000 to 3 x 30 000 formula
      cells (3 x 40 000 cells is now over the package opening limit and is refused);
   d. the shared-formula test gained a counted assertion (RegExp.prototype.test calls during mapWorkbook < 5 000 for
      90 000 cells) after a first mutation run showed that removing the formula memo survived the time bound alone;
   e. the serialization-failure test gained a TypeError case (`report_failed`) and a failure inside the mapping
      (simulated on one cell's text), after the service mapped every non-reader failure of the pure stage to
      `report_failed` (a RangeError while serializing stays `report_too_large`).
4. Design steps driven by measurement (05, intermediate section): the first scanner kept a tree of every kept element and
   used the regex entity decoder: 4 parts of 4 MiB of `&amp;` cost 550 ms / +475 MiB and 4 x 30 000 valued cells +154 MiB.
   The decoder now writes one buffer, element names are matched without allocation, and rows, cells and shared strings
   are streamed; maxTotalElements went from the planned 250 000 to 200 000 for memory margin.
5. A first full mutation run also had an uninformative "stream nothing" mutation (it disables the handlers, so it fails
   for functional reasons, not as a cost check); it was dropped. The final run (04) has M1-M10, all KILLED.
6. Scratch copies, all under <task> (never the repository): base (git archive of 0f7fba2), after and final (intermediate
   exports), final2 (export of the final working tree, used for the after probes), mut and mut2 (mutation copies). In
   <task>/base the two test files were temporarily replaced by the final ones to record the red-first run and then restored
   (sha256 equal to HEAD's, 02). No folder was removed; no file inside the repository was deleted.
7. fast-xml-parser is no longer imported by src/ (the bounded scanner replaced it; its char-by-char string building costs
   about 55-110 bytes and 70-300 ns per input byte, which no byte limit that still accepts a 64-sheet workbook can fit in
   the budget). package.json and package-lock.json are not owned paths, so the unused dependency stays; removing it is a
   follow-up for the coordinator.
8. src/server/routes/imports.ts needed no change: the service now turns every read, map, report or serialization failure
   into 422 `workbook_rejected`, so the route never sees one. src/client/importModel.ts is unchanged: the new reasons
   (too_many_attributes, tag_too_large, sheet_name_too_long, report_too_large, report_failed) show the existing generic
   text "The workbook cannot be read safely. The workbook was not stored."
9. Semantics that changed only for inputs no spreadsheet program writes (documented in the code): a part must be
   well-formed XML (attributes separated by white space, one root, nothing but white space outside it, a non-empty part);
   a `si` (shared formula) or relationship id over 255 characters is ignored; formula text is cut at Excel's 8 192
   characters; the mapping examines at most 1 024 characters of a cell's text (longer text is never a label, holiday
   name, date or time); CDATA text is no longer entity-decoded (XML rule); a sheet name over 100 characters is refused.

   roughly 0.5-0.7 s.

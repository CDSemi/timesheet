## Required changes

1. **Migration 0008** (`0008_bootstrap.ts`): the storage the bootstrap needs, for example
   a one-row table for setup tokens. Keep it minimal and audited, and register it in
   `db/migrations.ts`.
2. **CLI `bootstrap --config <file>`.**
   - It validates an owner-supplied JSON for the calendar, default policy and payroll.
     The shape follows `reference/examples/*.json`, and the file holds no personal data.
   - It creates the company calendar and default policy once. A second run on a
     bootstrapped database is refused.
   - It then issues a single-use setup token:
     - only its hash is stored;
     - it expires in 60 minutes;
     - it is printed once to the operator's terminal and never written to the server log.
   - It runs in production. The development seed stays refused in production.
3. **`POST /api/auth/bootstrap`** with `{token, email, display_name, password}`.
   - It creates the first administrator.
   - It is refused permanently once any administrator exists.
   - Expired, replayed or wrong tokens get 4xx and reveal nothing about why.
   - GET never consumes the token.
   - It is audited as a system event (actor NULL, per RBC-01).
   - The password policy matches the existing one.
4. **`SetupScreen.tsx`.**
   - It is reachable only while no administrator exists and the instance is configured
     for setup.
   - Use E-8 CSS tokens only; it must be accessible, and mobile-first.
   - The token is entered by hand. It is never placed in a URL or in browser storage.

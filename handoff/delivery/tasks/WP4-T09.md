- **Preview (`services/workbookImport.ts`)**:
  - Computes the SHA-256 first. If the same owner, hash and mapping v1 already exist, it returns that batch and
    stores nothing.
  - Otherwise it runs `previewWorkbook` (the WP4-T08 reader and mapping v1; formulas are never evaluated). A refused
    package is 422 `workbook_rejected` with `details.reason` set to the reader code, and nothing is stored.
  - It writes the source through `FileStore.put` before the row. Inside one IMMEDIATE transaction it re-checks the
    key, inserts the row and an `import.preview` audit row (actor = owner). The file is discarded on failure or a
    lost race.
  - Report: every slot with its date, label and clock cells and their `sheet!A1` sources; the reader's findings
    (unknown labels, duplicates, the 8.5-hour, Sunday and TODAY defects, floating holidays); the stored rules; and the
    conflict plan. The employee cell is stored by address only; its text never leaves the private source.
- **Commit**:
  - Runs in one IMMEDIATE transaction with no network or file I/O. It recomputes the plan against the current rows.
  - Every listed day needs an explicit decision. A missing one is 409 `decisions_required`; an unknown date is 422
    `unknown_decision`; a forbidden action is 422 `decision_not_allowed`. In each case nothing is written.
  - It writes only:
    - `timesheets` with `imported_unverified = 1` and version 1;
    - `day_entries` with `category_source = 'explicit'`, no leave minutes and no notes;
    - audit rows `timesheet.import`, `day_entry.import` (with the source cell) and `import.commit`, all with
      actor = owner;
    - the batch row.
  - It also creates the shared `pay_periods` row through the existing `ensurePayPeriodRow` when the period has none.
    The timesheet foreign key needs that row.
  - It writes no session, ledger event, revision, sign-off, job or delivery attempt.
  - A committed batch with identical decisions returns `replayed` with the first result. Different decisions get 409
    `import_already_committed`. Two concurrent commits produce exactly one result, because the IMMEDIATE lock and
    the state check are taken together.
- **Conflict semantics** (the most conservative reading; also stored in every report as `rules`):
  - The unit is a whole payroll period, because `imported_unverified` is a period flag.
  - A period is `new` only when the owner has no timesheet, day entry, session, OT leave request or ledger entry in
    it, its payroll date is one of the owner's calendar periods (Monday = payroll − 18), and it has ended in the
    reporting zone.
  - Days in a `finalized`, `imported`, `existing_app_rows`, `not_in_calendar` or `not_ended` period allow `skip` only.
    So a finalized, signed or submitted period, an imported period and a draft app period are never overwritten
    or merged.
  - The following allow `skip` only: an unknown label; "Off day (overtime used)" (no single day category); a missing
    or unexpected date cell; a duplicate date; a date outside the calendar.
  - A floating holiday, or a label read from a formula cache, allows `skip` or `import`.
  - A blank day is never imported and needs no decision. Clock cells are reported, never imported (O12).
  - Label mapping: Worked or Work From Home → `Worked` (wfh 1); Holiday or a holiday-table name → `Holiday`;
    Shutdown → `Shutdown`; Vacation → `Vacation`; Sick Day → `Sick`.
- **Open owner choices** (not invented; the safe default stands until the owner decides):
  1. May a draft app period receive imported days? Options: (a) never, the current behaviour; (b) a decision that

  2. How should "Off day (overtime used)" be represented? Options: `Off`; `Worked` with leave minutes B and kind

  3. May an unended (current) period be imported? The current answer is no.

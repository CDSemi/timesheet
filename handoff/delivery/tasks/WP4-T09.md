## Required changes

1. **Migration `0012_imports.ts`** (the next free number; the schema is at 11).
   - The `imports` table holds:
     - owner, source SHA-256, mapping version and state (`preview`, `committed`);
     - the private stored source, through the file store;
     - the report JSON, and the created and committed instants.
   - The idempotency key is owner + source SHA-256 + mapping version, with a unique
     index.
   - Migrations stay exclusive and checksummed. Test a fresh 1→12 run and an upgrade
     from a populated v11.
2. **Service `src/server/services/workbookImport.ts`.**
   - **Preview.**
     - Read the upload with the WP4-T08 reader and mapping v1. Never evaluate formulas.
     - Store the source privately, and store a report of:
       - the mapped days with their source cells;
       - unknown labels, duplicates and the template defects;
       - conflicts with the owner's existing app rows.
     - The same upload again returns the existing batch.
   - **Commit.**
     - Every conflict needs an explicit decision; the default is to import nothing for
       that day. A finalized, signed or submitted period is never overwritten.
     - Use one short transaction with no network inside. It writes only:
       - `timesheets.imported_unverified = 1`;
       - day entries with `category_source = 'explicit'`;
       - audit rows with actor = owner.
     - It writes no sessions (O12), no ledger events, no revisions, sign-offs, jobs or
       delivery attempts (F-2).
     - A repeated identical commit is a no-op that returns the first batch, including
       under two concurrent commits.
   - **Conflict semantics.** Choose the most conservative reading of the plan and
     docs/07:42, and record it in the report. If the contracts leave a business choice
     open, stop and report the options instead of inventing behaviour. One example:
     what happens to a draft app period that receives imported days.
3. **Routes `src/server/routes/imports.ts`, mounted under `/api/imports`.**
   - Upload and preview, read a batch, and commit with decisions.
   - Owner only (F-1):
     - another user's batch answers 404;
     - an administrator cannot import, preview or read for anyone else;
     - a share grantee cannot import or read the owner's imports.
   - Use a route-scoped upload limit like the signature exception, validated content
     type and size, and never the public static path.
   - Validate request schemas in `src/server/http/schemas.ts`.
4. **F-2 guards.** An `imported_unverified` period:
   - cannot be signed or submitted (409 `imported_period` in `finalization.ts`);
   - is read-only for day and session edits, also 409 `imported_period`;
   - posts no ledger events.

   Imported periods get no reminder, overdue record, deadline finalization or send. WP3
   already skips them in automation and notifications (O9); prove it with a test
   across simulated deadlines.

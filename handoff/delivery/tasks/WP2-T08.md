## Binding decisions

- **E-4.** A holiday import preserves employees' explicit day labels and manually added
  calendar dates. A manual date goes away only when it is removed explicitly. Default
  labels follow the calendar at read time, so the import never writes employee rows.
- **E-10.** A payroll exception refreshes the stored `pay_periods` row in the same
  transaction when no finalized timesheet references the row. Otherwise it is refused.
- **E-12.** From 1 October, warn when next year's company calendar dates are missing. Use
  an injected or fixed clock in tests; never depend on the real current date.

## Required content (from the plan)

- Holiday CSV import:
  - The format is `date,name[,kind]`, sent as a string field in the JSON body within the
    64 KB limit. Write the parser in src/domain/holidayCsv.ts as a pure function.
  - Preview writes nothing. It reports:
    - invalid dates, duplicates, empty names and out-of-year rows;
    - formula-leading cells (`=`, `+`, `-`, `@`, tab, CR);
    - a diff against the effective version: added, removed and renamed dates. Manual
      dates are kept unless the CSV removes them explicitly;
    - the affected default-labelled draft days and the preserved explicit overrides.
  - Commit carries the preview hash and an `effective_from` on or after the prospective
    boundary. It creates a new immutable calendar version and one audit event. An
    identical re-commit is a no-op and adds no version.
  - Finalized or old periods are never rewritten. The classification of past dates is
    unchanged after a commit.
- Payroll exceptions: admin-only create with a required reason, under E-10.
- The missing next-year calendar warning (E-12) is exposed as a field on the existing
  calendar read in routes/api.ts.
- Admin routes go in src/server/routes/admin.ts behind `requireAdmin`. Employees get 403.
- Covers:

  - AC-05 and R-07;

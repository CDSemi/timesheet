#### What was built

- `src/domain/emailTemplate.ts` (pure): closed variable set `EmployeeName`, `PeriodStart`, `PeriodEnd`,
  `PayrollDate`, `SignOffStatus`, `SubmissionId`, `Revision`. Unknown variable gives 422
  `unknown_template_variable`; unclosed, nested or stray braces give `invalid_template`; a subject template
  with CR, LF, NEL, LS or PS gives `template_line_break`. Values are neutralized to a single line (control
  characters and separators become one space), so a rendered subject never contains CR/LF. The HTML body
  escapes both values and template text (`& < > " '`) and turns LF into `<br>`; the text body is not escaped.
  Recipients: bare ASCII addr-spec only (no display name, comma list, quotes, IDN, IP literal, numeric TLD),
  trimmed, de-duplicated case-insensitively (first spelling kept; a `cc` address already in `to` is dropped),
  `to` required, `cc` optional, at most 10 per list after de-duplication (input list at most 40). A rejected
  address is never echoed; the error names the field and 1-based position.
- `src/server/services/submissionSettings.ts`: append-only versions (`submission_settings`, next `seq`,
  `expected_seq` gives 409 `stale_version`), all writes in `writeTransaction`, owner scoping from the session
  only, at most 500 versions per user. Audit events (`submission_settings.update`,
  `.auto_image_authorize`, `.auto_image_revoke`) carry flags, counts, ids, the effective instant and the
  signature SHA-256, never an address, template text or image.
  - Effective instant: the first save and every change of the auto-submit switch record "now" (so the change
    covers only periods not yet due); a save that keeps the switch carries the previous instant. Applying a
    change to already-overdue drafts is the explicit option `apply_to_overdue_drafts` (stored as
    `1970-01-01T00:00:00Z`, audited as `applies_to_overdue_drafts`); it is refused with 422
    `apply_to_overdue_requires_change` when the switch does not change. F-4: only the per-user instant is
    stored; `operations_state` is untouched and no activation is implemented.
  - Auto-image: default off; `authorize` references one of the caller's own signature attachments (another
    user's, a non-signature, an unknown or a malformed id all give 404; no saved settings gives 422
    `submission_settings_required`; the same image again gives 409 `already_authorized`); `revoke` is a
    separate audited version (409 `not_authorized` when nothing is authorized). Plain saves carry the
    authorization unchanged. Neither act creates `signed_at` or any review event.
  - Preview: `POST /api/settings/submission/preview` renders subject, text and HTML body from the caller's
    stored (or draft) templates with sample values for the current period (`SubmissionId` `PREVIEW`, revision
    1); it does not materialize the pay-period row and writes nothing.
- Routes (all session-required, owner-only): `GET /api/settings/submission` (current or defaults at seq 0),
  `GET /api/settings/submission/versions`, `GET /api/settings/submission/versions/:id` (own id, else 404),
  `POST /api/settings/submission`, `POST /api/settings/submission/preview`,
  `POST /api/settings/submission/auto-image/authorize`, `POST /api/settings/submission/auto-image/revoke`.
  Strict zod bodies in `schemas.ts` (unknown fields such as `user_id` give 422).

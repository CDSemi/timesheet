## Required changes (binding)

`POST /api/timesheets/:payrollDate/signoff` with `expected_version`, `reviewed_hash`,
`signer_name`, per-day deficit choices (deduct|waive where the policy mode is choose) and
the incomplete-evidence acknowledgement. One IMMEDIATE write transaction:

1. recompute the T04 snapshot and compare its hash and the timesheet version; a mismatch
   gives 409 with a fresh-review hint and writes nothing;
2. require the signer name and a current signature attachment of the same user (422
   otherwise);
3. create the immutable revision (origin employee, review signed) and the sign-off with
   the real `signed_at` from the injectable clock;
4. post credits and authorized debits only through `ledger.ts`, with revision-independent
   original keys per day; persist every proposal outcome in `revision_ledger_lines`,
   including the pending variants (R4) as the F-2 decision defines;
5. set `timesheets.finalized_revision_no`, so provisional minutes disappear for that
   period (posted plus provisional never double count);
6. enqueue the PDF and send jobs in `jobs` with unique business keys (the runner is T08;
   insert rows only);
7. audit without personal content beyond the canonical audit rules.

An identical retry after success is idempotent (same revision, no new ledger rows or
jobs). No network call inside the transaction.

#### Behaviour

`POST /api/timesheets/:payrollDate/signoff` body (strict): `expected_version`, `reviewed_hash`, `signer_name`,
optional `deficit_choices` `[{work_date, choice: deduct|waive}]`, optional `incomplete_evidence_acknowledged`.
`signOffTimesheet` runs one `writeTransaction` (BEGIN IMMEDIATE):

1. `buildReviewPayload` recomputes the T04 payload inside the transaction (a savepoint). A finalized period
   returns the existing result for an identical retry (same reviewed hash, signer name, choices and
   acknowledgement; 200 `replayed`) and otherwise 409 `already_finalized`. Then the version (409 `stale_version`)
   and the hash (409 `stale_review`) are compared; both 409s carry `{fresh_review_required: true}` and write
   nothing.
2. 422 `signer_name_required` / `invalid_signer_name` (NFC, trimmed, one line, at most 200), 422
   `signature_required` (the reviewed signature must be the owner's current one), 422 `acknowledgement_required`
   when the payload lists unresolved inputs, 422 `deficit_choice_required` / `unexpected_deficit_choice` /
   `duplicate_deficit_choice`.
3. The revision (`original`, origin `employee`, `signed`, revision 1, payload = the canonical reviewed payload,
   reviewed = payload hash, `send_requested` 1) and the sign-off (`signed_at` = the injectable clock at the
   request, not at review). A period with no saved row gets its timesheet row here.
4. Debits first, then credits, only through `postDeficitDebit` / `postCredit` with revision-independent keys
   `finalization:day:{date}:deficit_debit|credit` and `sourceRef` = revision id. Each deficit is decided by
   `decideDeficit` (the employee's choice in choose mode, the balance available now) and checked against the
   reviewed deficit minutes; `authorized` and `insufficient_balance` call `postDeficitDebit`, whose `pending`
   variant is recorded as `pending_insufficient_balance` (R4); `declined` is `waived`; `ignored` (policy mode
   ignore) records no line. Debits post before credits so each debit meets the balance the review showed (the
   review evaluates deficits before this period's credits); a test pins this.
5. `UPDATE timesheets SET finalized_revision_no = 1, version = version + 1` guarded by `finalized_revision_no IS
   NULL AND version = ?`; provisional minutes of the period disappear.
6. Two `jobs` rows (`render_pdf`, `send_email`), state queued, business keys `revision:{id}:render_pdf` and
   `revision:{id}:send_email:initial`, payload `{revision_id}` only. No runner, no file write, no network call.
7. Audit `timesheet.signoff`: ids, hashes, `signed_at`, outcome counts, job ids; no signer name, recipients or
   content (a test checks).

F-2 handling: a pending debit is an immutable `revision_ledger_lines` row of its revision with no ledger entry.
`GET /api/timesheets/:payrollDate/finalization` (review screen) returns the finalized revision, sign-off, all
lines and jobs; `GET /api/revisions/pending-lines` (OT screen) returns the owner's current pending lines (those of
each timesheet's finalized revision, so a later revision supersedes them). Both are read-only and owner-scoped.
Nothing posts a pending line later: a test adds 900 minutes, advances a week and finds no posting and no other
job kind. Sign-off stays strictly owner-only (no delegate path): a foreign payroll date is 404, an
administrator on the same calendar gets 409 (their own payload) and touches nothing.

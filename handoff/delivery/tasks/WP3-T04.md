#### What was built

- `canonical.ts` (pure, no Node API because the domain is also compiled for the browser): `canonicalize`
  sorts keys (UTF-16 order) after NFC, keeps array order, NFC-normalizes strings and keys, refuses duplicate
  keys after normalization, any non-safe-integer number (no floats, NaN, Infinity), `undefined`, Date, Map,
  class instances, cycles and nesting over 24 levels; `canonicalBytes` (UTF-8), `sha256Hex` (own FIPS 180-4
  implementation, checked in the tests against `node:crypto` for lengths 0-200, 100,003 bytes and the million-`a`
  vector), `canonicalHash`, and validators `canonicalDate`, `canonicalUtc` (whole-second `...Z` only) and
  `canonicalMinutes`.
- `snapshot.ts` (pure): the payload types, `normalizeReviewSnapshot` (validates every date, instant and minute
  count, orders days/proposals/reservations/ids), `sealReviewSnapshot` and `reviewSnapshotHash`. It computes no
  minutes.
- `reviewPayload.ts`: `buildReviewPayload(db, clock, user, payrollDate)` runs in one deferred transaction (payload
  and `expected_version` come from one consistent read; inside a caller's transaction it becomes a savepoint)
  and writes nothing. All minutes come from the engine: the timesheet view (`computeWorkDay` results),
  `provisionalCredits` for OT proposals and `decideDeficit` for deficits (the service throws if its deficit
  differs from the view's `deficit_minutes`).
- `GET /api/timesheets/:payrollDate/review` returns `{payload, payload_hash, expected_version}`. Anonymous 401;
  a payroll date that is not one of the caller's own gives 404 `not_found` (the existing domain 422 is mapped);
  a malformed date gives 422. Only GET is routed (POST/PUT/PATCH/DELETE give 404).

Payload fields (schema `timesheet-review`, version 1): `employee.name`; `period` (payroll, nominal payroll,
start, end, due date/time, `due_at_utc`, exception flag); `reporting_zone`; `submission` (`id`, `revision_no`,
`sign_off_status`); `timesheet.finalized_revision_no`; `calendar` (id, version ids); `policy.version_ids`;
`days` (14: date, day class/reason/holiday name/calendar version, category and source, attendance expected,
WFH, notes, leave minutes and kind, OT-leave counters and mismatch, sessions with breaks, completeness,
policy version, regular/nonworking/normal-excess/eligible/credited minutes, calculation error); `totals`
(the view's credited total and pending days); `ot_proposals`; `deficit_proposals` (mode, deficit, decision,
debit, balance seen); `unresolved_inputs`; `ot_leave_reservations` (unconsumed, with `use_due`);
`recipients` (to, cc, rendered subject, text and HTML body, template version); `signature` (attachment id and
SHA-256 or null); `auto_image` (authorized flag and attachment id); `show_ot_on_pdf`. No credential, no bytes,
no storage key, nothing that varies with the clock or the device zone (a test advances the clock, and a session
re-saved with another `input_zone` keeps the hash; `input_zone` and row versions are not part of the payload).

#### Choices within the contract (for the auditor)

- `SubmissionId` is derived, not a row id: `TS-<nominal payroll date>-<10 hex of SHA-256(user|calendar|period
  index)>`. A period without saved entries has no timesheet row and a GET must not create one; the id is stable
  across revisions and carries no name or address. `Revision` is the next revision number (max revision_no + 1).
- `SignOffStatus` renders "Signed by employee" (this is the manual sign-off payload; the deadline path in WP3-T10
  renders its own status).
- Deficit proposals are the engine's decision with no manual choice yet (`choose_at_signoff` is `pending`).
  Authorized debits are applied one after another to the balance the next day sees (`available_minutes_before`),
  because they post one by one (R-05); this is a subtraction of the engine's own debit, not a new calculation.
  The balance therefore enters the hash for periods that have a deficit.
- Unresolved inputs: `open_session`, `unconfirmed_breaks`, `calculation_error`, and `no_records` when the engine's
  deficit decision is `incomplete` (a normal Worked day with no record).
- Unconsumed reservations: every request with reserved minutes, plus `use_due` (leave date on or before the last
  day of the reviewed period), so the screen can flag the due ones (E-3).
- Notes are in the payload (a notes edit changes the hash; the PDF decides whether to print them). The explicit
  automatic-image authorization is in the payload (docs/03 "signature authorization").
- A finalized period (later revisions, corrections by difference) is not specialized here; that is WP3-T06.

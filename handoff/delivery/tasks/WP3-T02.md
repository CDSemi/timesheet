## Required changes (binding)

1. **Private file store** (`src/server/files/fileStore.ts`): write to a temp file, then
   atomic rename; record SHA-256; opaque keys (no user-supplied names in paths); an orphan
   temp sweep that never removes a file referenced by `attachments`. Nothing is ever
   served from the static root.
2. **Image check** (`src/server/files/imageCheck.ts`): accept only PNG and JPEG; the magic
   bytes and the declared content type must agree; bounded pixel dimensions; truncated or
   polyglot input is refused.
3. **Signature service and routes**:
   - `POST /api/signatures` accepts a raw `image/png` or `image/jpeg` body with a
     route-scoped size limit (default 256 KiB). The global 64 KiB JSON-only rule stays in
     force for every other `/api/*` route; prove it with a test. Origin/CSRF checks are
     unchanged for this route.
   - An owner-only `GET` returns the image with `Cache-Control: no-store` and an
     attachment disposition. Another user's ID gives 404; anonymous gives 401.
   - Replacing the profile signature creates a new immutable attachment; earlier
     attachment bytes and hash stay unchanged (later revisions reference them).
   - Audit the upload without storing image bytes or personal data in the audit payload.

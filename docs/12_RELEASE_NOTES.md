# Release notes

These notes identify the release candidate of the Timesheet application, state what each work package delivered, and list the limits and carried risks that a pilot user or operator must know. English is authoritative; [12_RELEASE_NOTES.vi.md](12_RELEASE_NOTES.vi.md) is the translation. They do not repeat the rules: each line points to the document or runbook step that owns it. The owner decisions D-1 to D-15 are listed in [WP5-PLAN](../handoff/delivery/tasks/WP5-PLAN.md) section D. **The owner answered all fifteen on 2026-10-20** ([10 Decisions](10_DECISIONS_AND_SOURCES.md)); each line below says which answer it follows. The pilot has not run and nothing is authorized.

## Software readiness, owner permission and pilot result

These are separate facts ([06 Acceptance](06_TEST_AND_ACCEPTANCE.md)).

- **Software readiness** means the gates and independent audits of the packages passed on synthetic data in capture mode on a developer workstation. It is recorded in the package handoffs and is not a statement about the NAS.
- **Owner permission** is the owner's explicit authorization of real sending and activation. It has not been requested or given in this release; nothing is deployed and no real email has been sent.
- **Pilot result** is what the owner observes in one real period with the Excel workbook still available. There is none yet.
- **Provider acceptance and recipient receipt** are also separate: the provider's acceptance of a message does not show that anyone received or read it ([05 Submission](05_SUBMISSION_AND_NOTIFICATIONS.md)).
- The NAS target is NOT VERIFIED until the owner ticks the [runbook](11_OPERATIONS_RUNBOOK.md) section 2 checklist (owner decision D-13 (a)). Without it the result is "software ready, pilot pending".

## Known limits and carried risks

Each line gives the limit and where the rule or step is. None is a known defect that blocks the pilot; the independent assessment found no blocking integrity, privacy or submission defect.

### Submission and mail

- **Reminder repeat after a crash on real SMTP (D-7).** A reminder may go out twice if the process stops while sending (at-least-once). Reminders are advisory. Owner decision (a): accepted and documented (D-7). [05 Submission](05_SUBMISSION_AND_NOTIFICATIONS.md) "Durable delivery".
- **TLS certificate failure is classified temporary (D-8).** A TLS certificate failure (untrusted, expired or wrong host name) is temporary in both TLS modes: it is retried, five attempts in all, then needs intervention, and shows as `smtp_unavailable`; `smtp_tls_failed` appears only when the server refuses STARTTLS. Owner decision (a): kept and documented (D-8). A failing send after a certificate or host change is a configuration problem to check first ([runbook](11_OPERATIONS_RUNBOOK.md) section 13).
- **Send before the PDF.** A send that runs before its PDF exists is retried once after about a minute; this is the documented retry, not a fault ([05 Submission](05_SUBMISSION_AND_NOTIFICATIONS.md)).
- **Real SMTP is unobserved.** Capture mode cannot show real provider behaviour. It is observed only in the staged first period ([runbook](11_OPERATIONS_RUNBOOK.md) section 13).
- **Never-configured accounts (WP3 R8, R-WA3).** Once automation is active, an account that never saved its submission settings, including the bootstrap administrator account, still receives before-due reminders. Save the settings of every account, or use only the accounts that have them, before activation ([runbook](11_OPERATIONS_RUNBOOK.md) section 16).
- **The reviewed-payload hash includes the OT balance (WP3 R4).** A review can go stale after an OT movement; reload and review again.
- **Sign-off before the period end is allowed (WP3 R5).** An accepted interpretation of [05 Submission](05_SUBMISSION_AND_NOTIFICATIONS.md).
- **Seed events show as automatic (WP3 R9).** Only synthetic seed data; the seed is refused in production.
- **A very long holiday label can still be cut with an ellipsis in the PDF (WP3 R1, R-WA6).** Since the round-5 PDF the category cell shrinks the label to 5 pt and wraps it on up to two lines first, and cuts it only when it still does not fit (`drawCategory`, `fitText`). The pilot samples have no holiday label; the owner judges it on a real one.
- **Partial leave is printed on the PDF since round 5 (R-WA2 no longer holds).** A day with leave prints "Leave h:mm" in small type under its category (read from the frozen code, `drawCategory`; the pilot samples have no leave day). On a day that also has a holiday label, the label is shrunk to one line and cut first; the leave figure keeps its own line. A day with 4 h work and 4 h leave still prints as worked time with its OT. The owner judges whether payroll needs more.
- **Days without records read "Worked" on an automatic PDF (R-WA8).** This is the owner's decision F-1 and F-Q1 (no automatic indicator, default labels), see [10 Decisions](10_DECISIONS_AND_SOURCES.md); the pilot sample shows it.
- **The outcome notice after downtime recovery is inexact (R-WA1).** It says the period was submitted "at the deadline" although a recovered submission is produced later; the PDF date is correct.
- **Unconfirmed breaks.** Check out is refused with 422 when a saved break ends after the Check out time (`saved_break_after_clock_out`), and a break in the future, one that ends more than five minutes from now, is refused when it is listed (`future_break`); an unconfirmed break that lies inside the session does not stop Check out, it only keeps OT pending. A refused Check out is resolved in the Check out dialog itself: list the breaks taken in its break rows, or tick "Confirm no breaks taken"; removing every saved row with the box unticked deletes them and keeps the breaks unconfirmed. "Confirm breaks" on a session card applies to ended sessions: it opens the session dialog, where Save confirms the listed breaks or "Confirm no breaks taken" ([02 Time and OT](02_TIME_AND_OT_RULES.md)).

No history is imported for the pilot; production keeps the import. [runbook](11_OPERATIONS_RUNBOOK.md) section 10.
- **More than 64 sheets are refused by the import (R-B4-3).** Only relevant if history is imported.
- **Owner choices and what they mean now:**
  - D-2 (WP4-I-1), answer (a): a draft period never receives imported days.
  - D-3 (WP4-I-2), answer (a): "Off day (overtime used)" is skipped.
  - D-4 (WP4-I-3), answer (a): an unended or not-yet-due period is skip-only.
  - D-5 (WP4-I-4), answer (a): a correction of the opening balance to a net zero is allowed (one offsetting correction; a balance already at 0 posts nothing).

### UI change round 4

- **The discard guard does not cover every way out.** The "Discard your changes?" question guards a day switch, the open day's button, "Open a day", "Today", the period steps, "Current period", Close and Escape. It does not guard a link that leaves the Timesheet page (the top bar, "Review & sign off"), and it does not guard the editor's reload after a label or batch commit changed the open day itself.
- **Company calendar file limits.** Working weekdays cannot be imported (no route changes them), so a file whose weekdays differ from the calendar is refused. The file applies to the administrator's own calendar, the only one the page reads. One holiday year is imported at a time. A payroll exception that already exists with other values is kept, because an exception cannot be edited. The holiday commit and each payroll exception are separate writes, so a failure part-way reports what was already written.
- **Classic scrollbars.** The 1345px figure for the beside layout with a classic scrollbar is computed from the tokens by a unit test and checked by a browser test that is launched without the headless default `--hide-scrollbars`, so a 15px scrollbar is drawn (the editor's layout rule takes the window width less the classic scrollbar width, measured once with an off-screen box, so it does not depend on whether the page draws a track and the editor no longer flaps between beside and floating; a page shorter than the window draws no track). Other browsers and operating systems with classic scrollbars were not tried.

### UI change round 5

- **A corrected or late revision is sent by the person only (owner decision H-1 a).** The deadline scan sends a period only when no revision of it has a send. If a copy was sent and the person then signs a correction and forgets to send it, payroll keeps the earlier copy and nothing sends the correction. The Timesheet button then reads "Review or correct", and the Review page's Send card still offers the send.
- **A queued send is not visible to the Timesheet button.** The button reads the revision list and counts an earlier revision as sent only from its delivery state; a send queued for an earlier revision that has no attempt yet is not seen, and an unreadable list counts as "an earlier send exists" (the quiet link).
- **A correction's send can wait behind an older send.** A send of one revision of a period is refused (409, "A delivery of this period is already in progress") while a send job of another revision of the same period still waits, so the older copy cannot arrive after the correction's. While the mail server is down, the older job keeps retrying on the ladder 1, 5, 15 and 60 minutes (about 81 minutes in all) and cannot be cancelled, so the correction's send can wait that long ([05 Submission](05_SUBMISSION_AND_NOTIFICATIONS.md) "Corrections and resends"). After a restore the same rule holds the release of a held send of an older revision (`superseded_by_later_send`).
- **Several stored PDFs per revision.** Each distinct choice of the time and OT rows is rendered once and kept (up to four variants per revision, never deleted); the administrator status shows one row per revision (the first stored file).
- **"PDF Preview" opens in a new tab.** The server's content security policy (`frame-ancestors 'none'`, `object-src 'none'`) forbids an inline viewer. The Review response has no sender address, so "From" says "the sender set on this server" until a revision exists, then shows the address of the send draft.
- **Fractional widths are proved on the style sheet in the suite.** Playwright's viewport cannot be set to 479.33px or 767.33px (125 % and 150 % scaling), so the suite proves those cases on the style sheet's text and the TypeScript queries and runs its browser sweep at whole pixels. An audit probe did reach them in a real browser (Edge at `--force-device-scale-factor=1.5`: a window resized through the DevTools protocol, or an about:blank frame of that width at that scale) and found each range rule on one side of the line; a browser regression test of those widths stays a recorded risk. The wordmark bound with the "Shared with me" switcher is a fixed 1280px, because the switcher's width depends on the owners' names.
- **Phone Day editor.** After "Save day fields" from the fixed foot with the body scrolled down, the notice "Day fields saved." is announced but is at the top of the body, not in view. A press on a bare part of the top bar closes the desktop drawer.
- **The container drill was not run for round 5 by its slices.** The slices ran typecheck, lint, unit, integration, the full e2e and the built-server smoke; the drill, the clean-export verification and the independent audits belong to the package-final gate.
- **Samples.** The pilot samples were regenerated from the round-5 freeze commit; see the [pilot packet](../handoff/delivery/WP5_PILOT_PACKET.md) section 3.

### Operations

- **Rollback residual (R-A3, D-1).** Jobs created after a rollback to an older schema are not held: the older build runs with `JOB_RUNNER=off` until reconciliation. Owner decision (a): kept and documented (D-1). [runbook](11_OPERATIONS_RUNBOOK.md) sections 8 and 15.
- **Concurrent openers of a new database (R-A2).** Start one instance and wait until it is healthy before any other process opens a new database ([runbook](11_OPERATIONS_RUNBOOK.md) section 16).
- **The CLI falls back to the development database without `DATABASE_PATH` (R-A8).** Production refuses a missing path; keep both paths explicit for host CLI use ([runbook](11_OPERATIONS_RUNBOOK.md) section 16).
- **A same-day prune removes the paired pre-upgrade backup (R-RA2, R-B5-5).** Copy that backup aside, or prune on another day ([runbook](11_OPERATIONS_RUNBOOK.md) sections 8 and 16).
- **Restore onto a dangling junction (R-RA9).** Restore into a new real folder ([runbook](11_OPERATIONS_RUNBOOK.md) section 16).
- **Backup status after a restore (R-B5-4).** A restored instance reports the backup as `never` until its own first backup ([runbook](11_OPERATIONS_RUNBOOK.md) section 7).
- **Status gaps.** The result of the last `--prune` is not recorded, the retention run is only in the JSON, and a held send cannot be dropped (release or leave it) ([runbook](11_OPERATIONS_RUNBOOK.md) sections 5, 7 and 12).
- **Image identity and base image (R-B5-1, R-B5-2).** See "Release identity".
- **The NAS is NOT VERIFIED (D-13).** See "Software readiness, owner permission and pilot result".
- **The activation instant has no screen.** The administrator status shows it; recording or clearing it is an API call ([runbook](11_OPERATIONS_RUNBOOK.md) section 13).

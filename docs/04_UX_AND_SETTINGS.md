Use hours/minutes, never 1.30 for 1h30. Display current viewing zone and saved accounting date. Keep ordinary flows free of DB/job terminology. Actual clock values are never stored from a schedule: a time becomes an actual value only when the person saves it. The new-session dialog pre-fills the start and end with the reference hours of the policy effective on that date (wall-clock times on the accounting date in the saved reporting zone, shown in the input zone) and, for a date before today in the reporting zone (the server's date), the suggested breaks that lie inside them; pre-filled values are marked as such and stay editable, and Save asks for confirmation first.

## Proposed defaults

| Setting | Default |
|---|---|
| Normal calendar / reporting zone | Mon–Fri / America/Los_Angeles |
| Display zone | Device/current zone; does not affect calculation |
| Reference / required work | 08:00–17:00 / 480 minutes |
| Breaks | 15+30+15 excluded; shift-relative suggestions requiring confirmation (pre-filled in the new-session dialog for a day before today, confirmed by Save) |
| N / M | 30 strictly exceeded / 30 nearest, exact midpoint down |
| Non-working-calendar time | All eligible, no B/N, same M |
| Deficit | ignore; optional auto_deduct or choose_at_signoff |
| Payroll / due | Anchor 2026-10-02, every 14 days; prior Tuesday 17:00 |
| Reminder offsets | 24 hours and 2 hours |
| Unsigned auto-submit | Enabled preference after sender setup; real sending remains disabled until activation |
| Automatic signature image | Asked at signature upload as one explicit, audited authorization, pre-selected; if unticked, no image on automatic submissions until the user authorizes it later in Settings |
| Automatic submission note line | Off; when on, the PDF and email show the user's text (default "Automatic submission") |
| Time rows on PDF | On; the per-send default of the "Time rows on the PDF" switch of the Send card |
| Show OT on PDF | On; can hide without erasing ledger; the per-send default of the "OT rows on the PDF" switch |
| Notifications / outbound | Email, optional ntfy / dry-run initially |

These are declared design defaults, not claims that every value was user-confirmed. Calculation/calendar settings need an effective date. Preview changes to future/draft defaults, preserve explicit overrides and immutable revisions, and warn if next year's company calendar is missing.

## Timesheet sheet

The Timesheet page shows the form of the Excel workbook and the PDF. The header block carries the title, "Employee:", "Payroll Date:" and "Period:"; the company name is in the top bar and is not repeated on the on-screen sheet (the PDF keeps its company header). Two bands, "WEEK 1" and "WEEK 2", each a square sheet with a header strip (week number and range) and running Monday to Sunday with the rows Day, Date, Category, Time, OT (h:mm) and Status. The header strip and the first column (the row names Day, Date, Category, Time, OT, Status and the worked rows) have a slightly stronger fill (`--sheet-head-strong`) than the date cells: 1.27:1 from the date cell in the light theme and 1.36:1 in both dark sets, with `--text` at 12.30:1 (light) and 9.91:1 (dark) and `--muted` at 4.59:1 (light) and 4.83:1 (dark) on it. Status is the only row the Excel form lacks: it only displays each day's status in words and a shape, never by colour alone (Complete, Running, Open session, Confirm breaks, No times, Missing record, Upcoming, Calculation problem); it is not a checkbox, and "No times" is drawn as a ring with a diagonal bar, not as an empty box. The "Worked hours" switch (off when the page opens, not stored; round 5, U5-18: it was "Show worked hours") adds exactly two rows, "Worked, workday" and "Worked, day off" (round 5, U5-20, so it is clear which day each line belongs to): on the seven-column sheet they are a band tinted with `--worked-line` under a 2px `--sheet-rule-strong` rule; on the compact table each day and its worked line are one group (one `tbody`): no rule between the day row and its line, the line indented, tinted with `--worked-line` and reading "Workday 8:00  Day off 0:00" (the full names stay for screen readers), and a 2px rule closes each group. `--worked-line` is a themed token (a light value and one dark value in both dark sets) and `--muted` and `--text` keep 4.5:1 or more on it; the server values are unchanged. The form header is a wrapping row (round 5, U5-16): the title and the field block share a row while both fit; otherwise the whole field block moves under the title, then its groups wrap one at a time from the end (Period, then Payroll Date), and the title or a value breaks by word only when it alone does not fit. Below the weeks sit a legend, the "Overtime Total :" box and the signature lines.

- Title gap (round 4, owner answer F-5): from 768px the title row of Timesheet and of Review is `--page-head-gap` (32px, `--space-6`) above the next block (the period card, and on Review the first block under the title); below 768px the head is as before.
- Paper sheet (round 4, owner answer F-5): the toolbar, the page messages, the batch bar, the form header, both week sheets, the legend, Overtime Total and the signature lines stand on one surface, the paper (`[data-paper]`; on Review it is the Preview card: a header bar with "Preview" and the status chips, then the sheet). The title row and the period card stay outside it. The paper is `--paper-surface` (the card colour), raised by `--elev-paper` (the `--elev-2` step), with the card corner (`--radius-lg`, 12px) and `--paper-pad` (16px) of padding; it differs from the page by at least 1.12:1 in both themes and clips nothing, so a lifted column's shadow, an open category list and the editor column lift draw over it. The toolbar, the week sheets and the footer keep their own style, layout and colours: the week sheets and the footer lose only their outer shadow (their 1px frame and header strip stay), and the signature and date lines stay in their two rows. In the compact form (below 480px, round 5, U5-22) the period card and the paper stand `--compact-edge` (8px) from each window edge (a negative inline margin of the page padding less that edge), keep the card corner, and the paper pads 8px at its sides, so the four-column table keeps the width it had before (358px at 390px, 8px of edge on both sides), nothing scrolls sideways, and the PDF does not change; on Review the check card, the Preview card and the Send card stand at the same 8px. Review is one column at every width: there is no checklist beside the paper (the checks moved into the Sign off dialog) and the page keeps its normal width.

- Category cell: the app category (Worked, Off, Vacation, Sick, Holiday, Shutdown), the holiday name for a Holiday, a second line for work from home or for OT-funded leave minutes, and a note marker. Excel's "Sick Day" and "Off Day (Overtime Used)" are not reintroduced: OT leave stays leave minutes with `leave_kind` ot (document 10, 2026-10-03 E-2). A day with no record shows no placeholder text; empty cells are blank.
- Every number is a server field shown as h:mm. The client computes no business minutes. The OT cell follows the PDF rule: the credited minutes of a complete day, "pending" while the day is incomplete or its breaks are unconfirmed, blank for a day without a record. "Overtime Total :" is the server's provisional credited total over all 14 days, including both Sundays, with a note when days are still pending; it equals the PDF total. The Excel formulas that conflict with the canonical rules are not reproduced (document 10, 2026-10-08).
- Formats are those of the PDF: US dates (MM/DD in the cells, MM/DD/YYYY in the header and period bar), durations as h:mm, times as 24-hour ranges such as 08:00 - 17:00 in the display zone (round 5, U5-07: one formatter, a spaced dash everywhere a range is shown, `+1` after an end on a later day; the PDF prints a start cell and an end cell, no range), with several sessions listed and a running session marked. A week-sheet cell shows the tight form "08:00-17:00" only when the spaced form would not fit on one line in its time cells, decided once per sheet so a sheet never mixes the two forms; a range never wraps, except a late end such as "22:00-06:00+1" that even the tight form cannot hold in a day cell at its least width (the 108px columns of the seven-column sheet, measured at 480 and 900px, and the narrowest phone cell), which breaks onto two lines rather than run over the next column. Prose ranges with "to" are unchanged. The accounting date stays the saved reporting-zone date.
- Non-working days (weekends, holidays and closures from the server calendar, never inferred from the weekday) carry one light tint with fine diagonal hatching. Today carries an accent top bar and a "Today" tag. A cell that needs input has an amber tint plus the Status text and shape. Columns chosen in batch mode and the column open in the Day editor are lifted: raised by a few pixels over a soft shadow with a 4px corner, never boxed in a heavy ring. A batch-selected column also has a light tint and its checked selection box; consecutive lifted days of a week form one group with one shadow around the group and none cast on a neighbour. The day open in the Day editor is marked as a whole by the same lift plus a 1px accent frame inside the column and a filled Day cell (a 1px frame on the row and a filled Day cell on a phone, where selection is a tint and the checked box without lift), and its day button carries `aria-current`. The marker combines with the Today bar and the batch selection on the same column, goes when the editor closes or when the day is not on the displayed sheet, keeps at least 3:1 contrast for the frame (measured 4.82:1 or more on every column surface beside the sheet; the drawer has no backdrop in either layout, so nothing dims the frame and the 3:1 figure no longer depends on the layout) and 4.5:1 for text, and never covers the open category picker. Under reduced motion the lift is static. Every day column is at least 108px wide (`--sheet-col-min`) so no word is cut inside the cell; from 480 to 929px (round 5: it was 768 to 929px), where seven columns do not fit the page and the paper's padding, the week card scrolls sideways inside itself and the page never does (it was 899px before the paper added 32px); the 4-column table is only for windows narrower than 480px. In the read-only Review, which has nothing inside the week cards to focus, a card that scrolls sideways is a named region (`Week 1, ...`) that takes focus (`tabindex="0"`) only while it overflows, shows the shared inset focus ring (2px accent and a 1px card-coloured gap) on all four edges of the card's visible box, and scrolls with the arrow keys (WCAG 2.1.1); the ring is drawn by a non-scrolling wrapper above the day columns, so the columns do not cover it and a sideways scroll does not move it; a card that fits adds no tab stop.
- Signature lines: "Employee Signature" shows the signer's name when signed, or the pending-review state, with the date in the saved reporting zone and a link to the Review (its words are those of the period card's link, round 5: "Review & sign off", "Review now", "Review & send" or "Review or correct"). "Manager Signature" shows "Not used yet" with an empty date. The signature image never appears on the Timesheet page. The lines and the link are absent in a shared view and for an imported period.
- Compact form (below 480px, round 5, owner decision F-6 a; it was below 768px): each week is a four-column table Day | Category | Time | OT, one row per day at least 54px tall, with no sideways scroll; the Status folds into the Day cell and the Time cell tint. A whole row opens the day editor, and the row of the day open in it is framed. The first screen shows the period card (the narrow arrangement: "<" and ">" beside the centred range, then "Today" and the Review link together in one row) and the compact tools, so the first day row is fully visible above the tab bar at 390x844 (measured in round 5, with the card and the paper 8px from the window edges and the paper's 12px of top padding: its bottom is at 582px, or 685px with the zone note, against the tab bar at 788px; 634px and 737px with a received share, whose switcher takes a second bar row; it was 571px, 670px, 623px and 722px in round 4), also in the five days when "Current period" joins that row (down to the narrowest phones, "Current" and "Sign off" keep the one row; see "Narrow arrangement buttons"). The page heading stays for screen readers only below 768px (the check in/out controls are in the top bar there, not on the page) and the form title below 480px. From 480 to 767px the shell is still the phone bar with the tab bar and the Day editor a bottom sheet, but the sheet is the seven-column grid scrolling sideways inside each week card (see above), so a wide phone or a small tablet keeps the full form (the WEEK bar is as wide as the grid under it, also after a sideways scroll, round 5, U5-21). Beside the Today marker the day button starts 8px after the bar, in every row (round 5, U5-19). ## Day editor

- Drawer (round 4, owner request of 2026-10-20, U4-05 to U4-07): from 768px the editor is a non-modal drawer (no backdrop, nothing inert, no `aria-modal`; the page stays usable), flush with one window edge from under the top bar to the bottom of the window. The drawer has no rounded corner (`border-radius: 0` on all four, docked right or left, in the light and both dark sets; round 5, U5-23: the owner's words "detail panel without rounded corners" reverse the round-4 corners). Phones (below 768px): a modal bottom sheet of at most 86% of the screen height with its top corners rounded (`--radius-lg`) and its bottom corners square; it is a grid of the handle, the head, the body (the only part that scrolls) and a foot (see "Order").
- Beside or floating: the Day editor floats only when the sheet and the drawer would not fit side by side, a rule of the window width alone (never of the mode the editor is in, so it cannot flap). `editorLayout` (`editorLayoutModel.ts`) returns `bottom-sheet` below 768px, `beside` when `viewportWidth - pagePadding - editorWidth - gap >= sheetMinWidth`, otherwise `floating`. `viewportWidth` is `window.innerWidth` less the width of a classic scrollbar (R5 b), measured once per device pixel ratio with an off-screen box that has `overflow: scroll` and 0 for overlay or hidden scrollbars; so the width never depends on whether the page draws a track at this moment (a track that came and went with the page height let the layout change the page height and so the width again), and the root is not forced to scroll: a page shorter than the window draws no vertical track; every other input is read in px from a token: `--page-pad` (16px each side), `--editor-width` (400px), `--editor-gap` (16px) and `--sheet-min-width` (the 92px label column, 7 x `--sheet-col-min` 108px, the 2px of hairlines and 2 x `--paper-pad` 16px: 882px). With the documented tokens the switch is at 1330px with overlay scrollbars (measured by the sweep test) and 1345px of window width with a classic 15px scrollbar; it replaces the fixed 1360px of round 3, which was 30 to 47px too early. Beside: the drawer is fixed on the right and the page reserves `--editor-width + --editor-gap` on that side, so the sheet is never under the drawer (16px or more clear) and every day column is at least 108px wide. Floating: the drawer lies over the sheet's edge, docked at the left edge instead of the right when the edited column lies in the right half of the screen, with the edited column scrolled into view. The page is not inert, so a control behind the drawer can take focus: when its box lies wholly under the drawer, the drawer docks to the other edge (WCAG 2.2 SC 2.4.11), so a focused control is never entirely hidden.

## Settings export and import

- Two files (round 4, U4-01; owner answers F-3 (a) and F-4 (a) of 2026-10-20), client only: each is made and read in the person's browser from the answers of the existing routes. No route was added and the server still checks every value. The file is JSON `{ "format": "timesheet-settings", "schema_version": 1, "app_version", "exported_at" (a UTC instant), "scope": "personal" | "company", "data" }` with snake_case keys equal to the API bodies, named `timesheet-settings-<date>.json` or `timesheet-company-calendar-<date>.json` (the date is the accounting date of the reporting zone).
- Personal file (Settings, Personal, card "Export and import settings"): the work policy (required minutes, N, M, reference hours, breaks, deficit mode), the submission settings (To and Cc, subject and body templates, the defaults "Time rows on the PDF" and "OT rows on the PDF" (the optional key `show_time_on_pdf`; an older file without it leaves the saved value as it is), reminder offsets, the automatic note line and text, and the automatic submission setting as data only) and, when ticked, the theme of this device. It never holds the signature image or its automatic-image authorization, a password hash, a session or setup token or any other secret, any timesheet data (days, sessions, breaks, leave, notes, the OT ledger or opening balance, revisions, PDFs, deliveries, audit events), a person's name, email address or id, or `apply_to_overdue_drafts`. The builders copy a fixed allowlist of keys one by one; the reader refuses an unknown format, schema version or key, an invalid value or time, and a file of the other scope, before any preview. The card says "Keep it private": the file holds the recipients' email addresses.
- Company file (Administration, card "Company calendar file", administrators only, for the administrator's own calendar): reporting zone, payroll schedule, working weekdays, holidays and closures, payroll exceptions; no person and no timesheet data. It is refused when its reporting zone, payroll schedule or working weekdays differ from the calendar (zone and schedule never change, and no route changes weekdays).
- Import always previews first, then needs one confirmation. The file is read in the browser; a dialog shows a table "Setting / Now / In the file" per group (a changed value is bold and carries the word "changed", an unchanged one reads "same"); "Import N changes" writes. Before it, the only requests are reads and the existing previews (the policy preview, and the holiday-import preview, which writes only its audit event); Cancel writes nothing. Personal: each group that differs becomes a new version through `POST /api/policies` (the work policy applies from a chosen date, by default the first day after the pay period that contains today and never before the current period's start, R-07; the policy preview lists the draft days that change; the note reads "Imported from settings file <name>") and `POST /api/settings/submission` (with `expected_seq`; a stale one reloads the comparison); the theme applies to this device only; a group equal to the current settings writes nothing. Automatic submission is never switched on by a file alone: a file saying "on" switches it on only with the separate tick "Also turn automatic submission on" (unticked, and offered only when it is off now); "off" in the file switches it off; `apply_to_overdue_drafts` is never sent. Company: the file's holidays and closures of one chosen year go through the holiday-import preview and commit (merge rule unchanged: dates the file does not list stay; effective date; finalized-period conflicts shown) and each new payroll exception through the payroll-exception route (an existing exception with other values stays as it is). These calls are separate transactions, so a failure after the first is reported together with what was already written.
- Access and loading: the personal card belongs to each signed-in person (the routes take the owner from the session; there is no shared path); the company card is shown to administrators only, and the server still answers 403 to the admin routes for anyone else. The card's code loads on demand. A refused file opens the alert "This file cannot be imported" with the reasons and "Nothing was changed". The file input is the native one with a visible label; the preview is a modal dialog with a real table (column headers, row headers, group headings), whose heading takes the initial focus; Escape or Cancel returns focus to the file input.

## Editing and review

Save in the session dialog confirms the listed breaks or the ticked "Confirm no breaks taken"; Check out does the same with its listed rows or box, and an empty list with the box unticked keeps breaks unknown. Unknown breaks or open intervals keep OT pending. Show explicit end date for overnight entry. Batch category changes must expose existing work conflicts and never silently delete clock evidence. Holiday work retains holiday classification and actual intervals.

Current/future draft edits audit automatically without a reason; old/finalized edits require one. Review flags attendance assumptions, incomplete OT and proposed deficits. The employee may acknowledge incomplete optional clock evidence and submit attendance. Invalid records require correction or explicit audited exclusion. Automatic submission uses valid saved attendance; for a period with no saved entries it uses the default labels (FR-03). Days without records credit no OT and create no deficit; incomplete days keep OT pending. The employee may add records later and correct the period (document 05).

Leave: the Day editor shows a non-blocking warning when the day's `ot`-kind leave minutes differ from the linked leave request's consumed minutes. It never spends or releases OT. The only way to consume reserved OT leave is the employee's "Record use" action; reservations not yet used stay visible as reserved.

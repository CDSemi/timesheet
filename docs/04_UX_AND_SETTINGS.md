Use hours/minutes, never 1.30 for 1h30. Display current viewing zone and saved accounting date. Keep ordinary flows free of DB/job terminology. Actual clock values are never stored from a schedule: a time becomes an actual value only when the person saves it. The new-session dialog pre-fills the start and end with the reference hours of the policy effective on that date (wall-clock times on the accounting date in the saved reporting zone, shown in the input zone) and, for a date before today in the reporting zone (the server's date), the suggested breaks that lie inside them; pre-filled values are marked as such and stay editable, and Save asks for confirmation first.

## Proposed defaults

| Setting | Default |
|---|---|
| Normal calendar / reporting zone | Mon–Fri / America/Los_Angeles |
| Display zone | Device/current zone; does not affect calculation |
| Reference / required work | 08:00–17:00 / 480 minutes |
| Breaks | 15+30+15 excluded; shift-relative suggestions requiring confirmation (pre-filled in the new-session dialog for a day before today, confirmed by Save) |
| N / M | 30 strictly exceeded / 30 nearest, exact midpoint down |
| Non-working-calendar time | All eligible, no B/N, same M |
| Deficit | ignore; optional auto_deduct or choose_at_signoff |
| Payroll / due | Anchor 2026-10-02, every 14 days; prior Tuesday 17:00 |
| Reminder offsets | 24 hours and 2 hours |
| Unsigned auto-submit | Enabled preference after sender setup; real sending remains disabled until activation |
| Automatic signature image | Asked at signature upload as one explicit, audited authorization, pre-selected; if unticked, no image on automatic submissions until the user authorizes it later in Settings |
| Automatic submission note line | Off; when on, the PDF and email show the user's text (default "Automatic submission") |
| Show OT on PDF | On; can hide without erasing ledger |
| Notifications / outbound | Email, optional ntfy / dry-run initially |

These are declared design defaults, not claims that every value was user-confirmed. Calculation/calendar settings need an effective date. Preview changes to future/draft defaults, preserve explicit overrides and immutable revisions, and warn if next year's company calendar is missing.

## Timesheet sheet

The Timesheet page shows the form of the Excel workbook and the PDF. The header block carries the title, "Employee:", "Payroll Date:" and "Period:"; the company name is in the top bar and is not repeated on the on-screen sheet (the PDF keeps its company header). Two bands, "WEEK 1" and "WEEK 2", each its own square card with a header strip (week number and range) and running Monday to Sunday with the rows Day, Date, Category, Time, OT (h:mm) and Status. Status is the only row the Excel form lacks: it only displays each day's status in words and a shape, never by colour alone (Complete, Running, Open session, Confirm breaks, No times, Missing record, Upcoming, Calculation problem); it is not a checkbox, and "No times" is drawn as a ring with a diagonal bar, not as an empty box. The "Show details" switch (off when the page opens, not stored) adds the rows "Worked on a workday" and "Worked on a day off". Below the weeks sit a legend, the "Overtime Total :" box and the signature lines.

- Category cell: the app category (Worked, Off, Vacation, Sick, Holiday, Shutdown), the holiday name for a Holiday, a second line for work from home or for OT-funded leave minutes, and a note marker. Excel's "Sick Day" and "Off Day (Overtime Used)" are not reintroduced: OT leave stays leave minutes with `leave_kind` ot (document 10, 2026-10-03 E-2). A day with no record shows no placeholder text; empty cells are blank.
- Every number is a server field shown as h:mm. The client computes no business minutes. The OT cell follows the PDF rule: the credited minutes of a complete day, "pending" while the day is incomplete or its breaks are unconfirmed, blank for a day without a record. "Overtime Total :" is the server's provisional credited total over all 14 days, including both Sundays, with a note when days are still pending; it equals the PDF total. The Excel formulas that conflict with the canonical rules are not reproduced (document 10, 2026-10-08).
- Formats are those of the PDF: US dates (MM/DD in the cells, MM/DD/YYYY in the header and period bar), durations as h:mm, times as 24-hour ranges such as 08:00-17:00 in the display zone, with several sessions listed and a running session marked. The accounting date stays the saved reporting-zone date.
- Non-working days (weekends, holidays and closures from the server calendar, never inferred from the weekday) carry one light tint with fine diagonal hatching. Today carries an accent top bar and a "Today" tag. A cell that needs input has an amber tint plus the Status text and shape. Columns chosen in batch mode and the column open in the Day editor are lifted: raised by a few pixels over a soft shadow with a 4px corner, never boxed in a heavy ring. A batch-selected column also has a light tint and its checked selection box; consecutive lifted days of a week form one group with one shadow around the group and none cast on a neighbour. The day open in the Day editor is marked as a whole by the same lift plus a 1px accent frame inside the column and a filled Day cell (a 1px frame on the row and a filled Day cell on a phone, where selection is a tint and the checked box without lift), and its day button carries `aria-current`. The marker combines with the Today bar and the batch selection on the same column, goes when the editor closes or when the day is not on the displayed sheet, keeps at least 3:1 contrast for the frame (measured 4.82:1 or more on every column surface) and 4.5:1 for text, and never covers the open category picker. Under reduced motion the lift is static. Every day column is at least 108px wide (`--sheet-col-min`) so no word is cut inside the cell; from 768 to 899px, where seven columns do not fit the page, the week card scrolls sideways inside itself and the page never does.
- Signature lines: "Employee Signature" shows the signer's name when signed, or the pending-review state, with the date in the saved reporting zone and a link to the Review. "Manager Signature" shows "Not used yet" with an empty date. The signature image never appears on the Timesheet page. The lines and the link are absent in a shared view and for an imported period.
- Phones (below 768px): each week is a four-column table Day | Category | Time | OT, one row per day at least 54px tall, with no sideways scroll; the Status folds into the Day cell and the Time cell tint. A whole row opens the day editor, and the row of the day open in it is framed. The first screen shows the period card (with "<" and ">" beside the title, and "Today" and the Review link together in one row) and the compact tools, so the first day row is fully visible above the tab bar at 390x844 (measured: its bottom is at 559px, or 658px with the zone note, against the tab bar at 788px; 611px and 710px with a received share), also in the five days when "Current period" joins that row (down to the narrowest phones, "Current" and "Sign off" keep the one row; see "Phone buttons"); the check in/out controls are in the top bar, not on the page; the page heading and the form title stay for screen readers only. Both layouts expose exactly one element per day, named by weekday and date, with one day button whose accessible name holds its visible text and keeps the accounting date (WCAG 2.2 SC 2.5.3): "Edit {MM/DD} ({date})" on the sheet, for example "Edit 09/28 (2026-09-28)", and "Edit {weekday} {MM/DD} ({date})" on a phone, for example "Edit Mon 09/28 (2026-09-28)"; "View" replaces "Edit" when read-only.
- The Review uses the same sheet. In a shared view, the share bar stays above the period bar and controls outside the share are absent.

## Period bar, check in/out and batch mode

- Period bar: a two-row card from 768px. Row one has the title (the period dates joined by an arrow, "09/28/2026 → 10/11/2026", which screen readers read as "to") with a coloured pill (old amber, current green, future pink, or "in progress" blue for the period that contains today while the period before it is still the current one; a status such as "Draft" is a neutral grey pill) and the buttons Previous, Next, Today, Current period (when it applies) and "Review & sign off", in that order (the Review link is disabled with its reason for an imported period). Row two, under a hairline, holds the payroll date, the due date in words with the reporting zone, where "Due" is a label in the same style as "Payroll date" and the date and time keep the value style (for example "Due Tue 12/08/2026, 17:00 (America/Los_Angeles)"), and the viewing-zone phrase; these parts share one line when there is room and wrap onto further lines when there is not. The card carries exactly one status group (review and delivery). The bar always names the current viewing zone compactly (for example "Times in America/Los_Angeles"), also when it equals the reporting zone; each day in the sheet keeps its saved accounting date. The reporting zone, display zone, the due time in the display zone and the explanation of accounting dates versus session times show in an extra note only when the display zone differs from the reporting zone. A banner says when edits to the period require a reason.
- Today: always shown. It opens the period that contains today's date in the timesheet's saved reporting zone (the server's date, never the device zone), shows today's column and moves an open Day editor to today. It is inactive (`aria-disabled`, still focusable, dimmed with colours) when the sheet already shows today and the editor, if open, is on today; a press on the inactive button re-reads the server's date and moves to today's period only when the date has changed (for example after midnight in the reporting zone), otherwise nothing moves. The periods are also re-read when the window regains focus or the tab becomes visible.
- Current period: returns to the period the page opens on, the current period of R-07 (document 02). It is shown only in the five days from the Monday after a period ends to its payroll Friday, and only while the sheet shows another period; it only navigates and leaves the editor alone. In a shared view both buttons use the owner's zone and dates. Each jump is announced in a hidden polite status region.
- Phone buttons: Previous and Next stay beside the title; Today, Current period (when shown) and the Review link share one row at every phone width down to 320px. Each button stays 44px high on one line and shows its full label when that fits and a short form otherwise: "Sign off" for "Review & sign off" (and "Review" for "Review now" and "Review or correct") below about 22.8rem of row width, then "Current" for "Current period" below about 18.4rem; only below about 15.4rem (no real phone) does the Review link take its own row with its full label. The accessible names are always the full labels ("Current period", "Review & sign off"). Desktop shows the full labels.
- Check in/out: one state-aware button. Checked out shows "Checked out" and "Check in"; checked in shows "Checked in since HH:MM" with a static ringed dot and "Check out", which opens the break confirmation. On a desktop it is a group at the right end of the Timesheet page's title row (the state words right-aligned over the date line, no card). On a phone the same state and button are a group in the top bar on every screen of the person's own context (the bar is 60px high, or 112px when the "Shared with me" switcher takes a second row), so the group is not on the page; the break confirmation is the same dialog and focus returns to the button that opened it. It is absent in every shared view, on any width (the owner's check in/out stays the owner's).
- Toolbar: "Open a day" (its words, the date field and the "Open day" button on one row at every width; on the narrowest row, below 21rem, the words are hidden and the field keeps its accessible name; any date, also outside the displayed period; Today brings the sheet back), the "Show details" switch and "Change several days" (an outlined button until pressed, set apart from the switch by a 24px gap and a hairline separator from 768px). Batch mode is off by default: the selection boxes, "Select all", "Clear", the category choice ("Category for selected days") and "Preview changes" appear only after "Change several days" and leave with "Done". Batch category changes still preview conflicts with recorded work before saving. Without edit rights (view-only share) and for an imported period these controls are absent or disabled with their reason.

## Day editor

- From 1360px: a non-modal panel in its own column beside the sheet (the page widens to 1600px while it is open), so the sheet stays visible and usable with every day column at least 108px wide. From 768 to 1359px, where the sheet and the panel do not fit side by side, the panel floats: a modal side panel over a light backdrop with the page behind it inert (focus stays inside the panel), so it never covers a control that can take focus; it is docked at the left edge instead of the right when the edited column lies in the right half of the screen, and the edited column is scrolled into view so it is never under the panel. Phones (below 768px): a modal bottom sheet of at most 86% of the screen height. Focus moves to the panel heading on open; Escape closes the panel wherever focus is (a nested dialog takes Escape first), as does Close, and focus returns to the day's date button. While the panel is open, the day it edits is marked on the sheet (see "Timesheet sheet").
- Header: on its own surface, with the title "Mon 10/12/2026" (the dialog name keeps the ISO accounting date), a Close icon button and chips: the period (current, old, future or in progress), "Times in {display zone}", "Day in {reporting zone}" only when the display zone differs from the reporting zone, and "View only" for a read-only share. There is no long note about zones; the explanation of the input zone sits beside the "Input zone" field of the session dialog.
- Order: the header, a status banner, the stale/notice/error messages and the reason field (old or finalized periods), "Times" (one card per session with its range, a state pill, its source line and a break table, plus Add session), "Category and leave" and "Figures (computed by the server)". The panel only shows the chosen times and breaks; the explicit end date and the visible "Input zone" are in the session dialog, and the day fields keep their own button ("Save day fields").
- Session cards: the range in the display zone (`+1` when the end is on a later local day), a pill ("Breaks confirmed" or "No breaks taken" green, "Breaks not confirmed" amber, "Running" with a static dot), a source line ("Entered by hand in {zone}" or "Checked in and out") and the break table (Break, Date, Start, Minutes, in the display zone). A session with unconfirmed breaks shows "OT stays pending until breaks are confirmed." and a "Confirm breaks" button that opens the session dialog with its saved rows or, when it has none, the suggested breaks that lie inside the session; if none fits, Save asks through the notice below. The old one-tap buttons no longer exist. Edit and Delete are absent in a read-only share or an imported period.
- Session dialog: Add session, Edit and Confirm breaks open a modal dialog (720px wide, full screen below 768px) titled "New session" or "Edit session" with the accounting date and reporting zone, a Time section (start and end date and time, the overnight note, the "Input zone" with its explanation) and a Breaks section; in an old or finalized period it shows the reason field. A new session is pre-filled (see the rule at the top): the reference hours and, only for a date before today in the reporting zone as the server reports it (never the device clock), the suggested breaks inside the session, with a note, a "suggested" tag on untouched suggestions, and suggestions that follow the start time until a break is edited. On a phone the head and the two 44px buttons stay in view while the body scrolls.
- Break rows: one row per break with "Break n", start time, minutes (1 to 720) and a remove button; the end is computed ("ends 10:15") because a break's end is its start plus its minutes (elapsed time, R-07). The break date field appears only when the session crosses local midnight or has no end yet; otherwise a break is on the session's date. One checkbox, "Confirm no breaks taken", hides and disables the rows (kept and restored when unticked); "Suggest breaks" and "Add break" add rows. A nonexistent or ambiguous local time raises the usual prompt naming "Break n". A row is one line from 42rem, two lines below that ("Break n", then the fields), and below the measured width (a list of 268px for a same-day row, 390px for an overnight row) each break is a chip such as "Break 1 · 10:00 → 10:15" (24-hour; the start date only for an overnight session) that opens a "Break n" sub-dialog with date (if shown), start time, minutes, Remove break, Cancel and Done; nothing is saved until the session is saved. Row and server errors mark the row or chip.
- Save and cancel: Save validates, then, with no break listed and the box unticked, a notice "No breaks listed" offers "Confirm no breaks taken", "Leave breaks unconfirmed for now" and "Go back and add breaks" (Escape is Go back); a save always ends with a confirmation "Save this session?" listing day, time and breaks, with Back and Save. Saving confirms the listed breaks (or none); an unconfirmed save keeps breaks unknown and OT pending. Cancel, Close and Escape ask "Discard your changes?" (Keep editing, Discard) only when something changed. At most one modal is on top at a time and Escape closes only that one; focus returns to the control that opened it, or to the "Times" heading after a save.
- Delete: "Delete" opens an alert dialog "Delete this session?" listing day, time and breaks, with "Cancel" (initial focus) and "Delete session"; in an old or finalized period it shows the reason field and waits for it.
- Check out dialog: the same break rows and chips under the title "Check out", with the "Confirm no breaks taken" box. The date field is always shown there (a running session has no end yet). The buttons say what happens: "Check out, no breaks taken", "Check out with these breaks" (the listed rows replace the saved ones) and "Check out, breaks unconfirmed" (an empty list and an unticked box omit the list: breaks stay unknown and saved rows are kept). The notice above is not used at Check out. When its rows or the "Confirm no breaks taken" box changed, Cancel or Escape asks "Discard your changes?" (Keep editing, Discard) and with no change it closes at once; Check out itself shows no notice and no final confirmation.
- WFH: in "Category and leave" the "Worked from home (WFH)" checkbox sits on the same row as the Category choice and wraps below it only on the narrowest widths.
- Leave is typed as "Leave hours" plus "Leave minutes" with "Leave kind"; the page converts them to the same whole `leave_minutes` (0 to 1440) and refuses fractions or out-of-range values with a message on the page.
- Category in the cell: on an editable sheet the Category cell is a picker (Worked, Off, Vacation, Sick, Holiday, Shutdown and "Work from home" = Worked with WFH) operated by mouse or keyboard. The open picker has a 1px accent line, the active option (keyboard or pointer) has a light fill and an accent rail on its leading edge without a frame, and the current value is shown in accent text with a check. A pick is first sent as a one-entry batch preview and commits immediately only when the preview needs no reason and shows no conflict with recorded work; otherwise the existing review dialog ("Review category change for {date}") asks for the confirmation or reason. The picker is absent in a view-only share, in batch mode and for an imported period.

## Editing and review

Save in the session dialog confirms the listed breaks or the ticked "Confirm no breaks taken"; Check out does the same with its listed rows or box, and an empty list with the box unticked keeps breaks unknown. Unknown breaks or open intervals keep OT pending. Show explicit end date for overnight entry. Batch category changes must expose existing work conflicts and never silently delete clock evidence. Holiday work retains holiday classification and actual intervals.

Current/future draft edits audit automatically without a reason; old/finalized edits require one. Review flags attendance assumptions, incomplete OT and proposed deficits. The employee may acknowledge incomplete optional clock evidence and submit attendance. Invalid records require correction or explicit audited exclusion. Automatic submission uses valid saved attendance; for a period with no saved entries it uses the default labels (FR-03). Days without records credit no OT and create no deficit; incomplete days keep OT pending. The employee may add records later and correct the period (document 05).

Leave: the Day editor shows a non-blocking warning when the day's `ot`-kind leave minutes differ from the linked leave request's consumed minutes. It never spends or releases OT. The only way to consume reserved OT leave is the employee's "Record use" action; reservations not yet used stay visible as reserved.

## Visual standard

Plain CSS custom properties in `src/client/styles.css`; system font stack only (the content security policy allows no web fonts), with numbers, times and OT in the monospace stack. New values are added as custom properties, never as ad hoc values.

- Style (round 3, owner decision of 2026-10-15; it replaces the industrial direction, the 4px radius and the 300 ms transition of E-8): a modern, friendly business style. Surfaces step from the page (`--bg`) to cards (`--card`), then sheets, panels and menus. Every colour has a light value in `:root` and the same dark value in both dark sets; a card differs from the page by at least 1.12:1 in both themes. One brand accent (`--accent`); status colours and the period pills (`--pill-*`: old amber, current green, future pink, in progress blue, neutral grey) always carry words or a shape.
- Shape (radius scale): inputs and chips `--radius-sm` 6px; buttons and inset panels `--radius` 8px; cards, the period bar, dialogs, the editor panel and menus `--radius-lg` 12px; pills and the avatar `--radius-pill`. Exception: the week sheets and the sheet footer are square (`--radius-sheet`, 0), because the sheet keeps the Excel form; a lifted (selected or open) sheet column has a 4px corner (`--radius-lift`).
- Elevation: a hairline ring plus soft layered shadows, never a hard border. `--elev-bar` the top bar, `--elev-1` cards and the period bar, `--elev-2` the week sheets, the footer card and the docked editor, `--elev-3` menus, dialogs and the floating panel, `--elev-lift` a lifted sheet column. The dark levels carry a light ring because a shadow alone is invisible on a dark page. The Timesheet page shows the toolbar and the form header on the page and each week band as its own card with a header strip (week number and range), so the sheet stands out from the page.
- Motion: one shared transition token (`--transition`) that lists only the properties that change (colour, background, border colour, box shadow, transform) and never `all`; `--duration` 180 ms (`--duration-fast` 120 ms, `--duration-slow` 260 ms) with `--ease-standard`. A control that needs another duration sets `--transition-duration` on itself. A pressed button moves by a small token offset. No entrance, scroll or looping animation; under reduced motion the durations are 0.01 ms, and the running-session dot is static.
- Buttons: primary (accent fill), secondary (card with accent border) and quiet (accent text), each with a visible focus ring (one shared token: a solid accent ring with a card-coloured gap, at least 3:1 against every surface in both themes).
- Hover and pressed: secondary and quiet buttons, navigation links, tabs, the More entries, switches and picker options share one hover tint (`--hover-fill`) with an accent boundary; a pressed (toggled-on) button is a solid accent fill with its on-accent text, and under the pointer it turns to the stronger accent, so hover never hides the pressed state. Hover looks apply only on devices that can hover (`@media (hover: hover)`), so a tap leaves none. Measurable criterion, in both themes: the hover fill differs from the resting surface by at least 1.20:1, the accent boundary reaches 3:1 against the surface, text on the fill keeps 4.5:1, and the pressed fill differs from the unpressed hover fill by at least 3:1.
- Touch: controls are at least 44px (`--tap-min`) below 768px and with a coarse pointer.
- Day-state colour roles (sheet rules and heads, non-working tint with hatching, today, needs input, selected, editing, running) have light and dark values. State is never colour alone: every state also has words or a shape.
- Brand: the logo and the wordmark are brand artwork in fixed colours, not restyled with the interface colours. The logo is a vector file; the wordmark is vector outlines drawn in the page, and no font file is shipped. In the dark theme the wordmark uses documented lighter tints of the brand blue and grey so it stays readable; the light theme keeps the brand colours.
- Mobile-first layout with readable density for a small-team timesheet app (clear hierarchy and comfortable spacing; the sheet keeps its Excel form). Light and dark themes follow the device until the person chooses one with the "Theme" control (Light or Dark, each with a sun or moon icon, in the desktop account menu and in the phone More panel); the choice is stored on that device only, with no server setting, and is applied before the page is drawn.

## Email and PDF

Variables: {EmployeeName}, {PeriodStart}, {PeriodEnd}, {PayrollDate}, {SignOffStatus}, {SubmissionId}, {Revision}. Reject unknown variables; escape HTML values and validate recipients. Show setup/review previews. Normal email does not automatically include private OT notes or approval evidence. {SignOffStatus} renders "Submitted" for every submission, or the note text when an automatic submission's note line is on.

PDF: company header, salaried-exempt timesheet title, employee, payroll date, two Monday–Sunday blocks, dates/categories, optional time/OT rows, the credited OT total in h:mm over all 14 days, including both Sundays (hidden with the OT rows when Show OT on PDF is off), employee name/image/date and blank manager signature/date unless a real future approval exists. Use US Letter portrait, embedded Unicode fonts, readable long labels and bounded signature image. Remove stale year headers. Add submission/revision identifiers and sanitized filenames.

Manual sign-off requires both the employee name and a validated uploaded signature image. The unsigned automatic-image setting is separate.

The outgoing PDF and email of an automatic submission show no automatic indicator: the signature block prints the employee name and the date of the automatic submission in the saved reporting zone; the signature image appears only when the user has authorized automatic image use; a note line appears only when the user turns it on (default off; the user edits its text, default "Automatic submission"). The system still records the revision as automatic with employee review pending, empty signed_at and no sign-off, and the employee's own screens show that. Even a preauthorized signature image creates no signed_at or real sign-off. A separate OT evidence report can be exported when the user chooses.
